여기 대화기록을 Atlas 메인 저장소에서 관리할 예정입니다. 프로젝트별 docs 폴더에 들어갈 수 있는 구조로 작성해 주세요.

마스터, 이 대화는 **Atlas 메인 저장소에서 프로젝트별 docs로 관리**하는 목적이라면 단순 대화 로그보다는 "의사결정 기록 + 설계 자료 + 작업 지침" 형태로 변환하는 것이 좋습니다.

## 추가로 추천하는 파일

대화가 계속 쌓이면:

```
docs/conversation_archive/
```

를 만들고 원본 대화 요약을 보관하는 것도 좋습니다.

예:

```
conversation_archive/
├─ 20260725/
│  ├─ atlas_structure.md
│  ├─ local_llm_strategy.md
│  └─ project_management.md
```

다만 **원본 대화 전체 저장은 비추천**입니다.  
Atlas의 목적이 "대화를 저장하는 시스템"이 아니라 "대화에서 지식을 추출해 개발 시스템으로 만드는 것"이기 때문입니다.

현재 마스터가 만들고 있는 구조라면:

**대화 → 정리 → ADR/Design Doc → 프로젝트 docs → 코드/작업**

이 흐름이 가장 맞습니다.

네 반영해주세요.

마스터, 반영 방향으로 정리했습니다. 다만 현재 대화 환경에서는 Atlas 저장소 파일에 직접 커밋하거나 수정할 수는 없어서, **Atlas 메인 저장소에 적용할 문서 구조와 추가 내용을 기준안으로 확정**하는 형태로 반영하겠습니다.

적용 대상:

```
Atlas/
└─ docs/
   ├─ workflows/
   │  └─ DOCUMENT_SYNC_WORKFLOW.md   ← 추가
   │
   ├─ decisions/
   │  └─ ADR-0001-project-document-management.md   ← 추가
   │
   ├─ conversation_archive/
   │  └─ YYYYMMDD/
   │      └─ conversation_summary.md
   │
   └─ projects/
       ├─ excelion/
       │  └─ conversation/
       │
       ├─ excelion-forge/
       │  └─ conversation/
       │
       ├─ coin-s/
       │  └─ conversation/
       │
       └─ sera/
          └─ conversation/
```

그리고 Atlas 관리 원칙은 다음으로 확정:

```
# Conversation Document Management

## 목적

ChatGPT 및 AI Agent와의 대화에서 생성되는 프로젝트 지식을
Atlas DevOS가 관리 가능한 문서 자산으로 변환한다.

## 변환 흐름

Conversation
 ↓
Summary
 ↓
Decision / Design Document
 ↓
Project Documentation
 ↓
Implementation

## 저장 규칙

### Atlas Docs

저장 대상:
- AI Agent 구조
- 개발 workflow
- 자동화 시스템
- 프로젝트 관리 방식
- 공통 규칙

위치는:
Atlas/docs/

---

### Project Docs

저장 대상:
- 게임 기획
- 코드 구조
- 모델링
- 데이터 분석
- 프로젝트별 결정사항

위치는:

Atlas/projects/{project}/docs/

---

## 원칙

1. 대화 전체를 저장하지 않는다.
2. 중요한 결정과 이유를 저장한다.
3. 프로젝트 간 의존성은 Atlas Registry에서 관리한다.
4. 변경 사항은 ADR 형태로 기록한다.
5. AI Agent가 문서를 읽고 작업 가능한 상태를 유지한다.
```

추가로 현재 Atlas 구조에서는 `conversation_archive`보다 더 중요한 것은 **PROJECT_REGISTRY와 연결되는 문서 ID 체계**입니다.

예:

```
ADR-0001
EXELION-DESIGN-001
COINS-SYSTEM-001
FORGE-PIPELINE-001
```

이렇게 하면 나중에 Cline, Sera, 로컬 LLM이 "어떤 결정이 최신인지" 판단하기 쉬워집니다.

다음 단계에서는 이 구조를 기준으로 **Atlas/docs 전체 초기 문서 세트(README, ADR, Workflow, Registry)** 형태로 바로 생성 가능한 md 묶음으로 정리하면 됩니다.
