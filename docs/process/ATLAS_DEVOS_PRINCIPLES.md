# Atlas DevOS Principles

## Core Position
Atlas is no longer a feature-first framework. It is a platform that grows through Forge-driven requirements.

## Operating Model
- Forge defines the mission.
- Atlas executes the mission through runtime, decision, memory, event, plugin, and connector layers.
- Atlas only grows when a real mission exposes a missing capability.

## Rule of Growth
When Forge needs a capability, Atlas adds it.
When Atlas has no mission-driven need, it does not expand just for expansion's sake.

## Mission-Driven Development
1. Forge identifies a concrete need.
2. Atlas exposes or improves the missing capability.
3. The capability is exercised through a workflow test.
4. Forge validates the result.
5. Atlas improves based on the validated outcome.

## Platform Role
Atlas provides:
- workflow orchestration
- decision execution
- memory management
- event routing
- plugin lifecycle handling
- connector integration
- review and audit hooks

Forge provides:
- actual creative or production missions
- concrete requests and use cases
- end-to-end validation scenarios
