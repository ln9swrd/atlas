# Excelion Design Review — 2026-07-30

출처: chat 기획·설계 점검 → state 저장

엑셀리온은 게임(미션 기반 3D 메카 액션) + 오리지널 IP이다. 문서 기준 주제별 정리와 점검.

## 1. 장르 · 포지션

| 항목 | 확정 방향 |
|------|-----------|
| 장르 | Mission-Based 3D Action (오픈월드·대규모 RPG 아님) |
| 과거 변경 | Tower Defense → 미션 액션으로 전환 |
| 엔진 | Unreal Engine |
| 규모 | 1인 개발 가능한 범위, 맵·적·시스템 재사용 |
| 목표 단계 | Prototype → Vertical Slice → Steam |

**점검:** 장르 메시지는 문서 간 일치. “액션 RPG” 표현과 “Mission-Based 3D Action”이 혼용되나, 루프는 미션 액션이 중심.

## 2. 비전 · 설계 기둥

- **IP 우선:** 게임 = IP를 알리는 첫 작품 (STL, 설정집, 후속작 염두)
- **메카가 주인공:** 레벨·숫자보다 EXCELION 자체가 기억되어야 함
- **보스·연출·진화**가 핵심 보상
- **완성·출시**가 미완성 이상보다 우선
- 판단 3문: 더 재미? / 더 기억? / 1인이 끝까지?

**점검:** 기둥과 비전 문서가 잘 맞음. Charter의 Sera 역할은 D19와 충돌 → 문서 갱신 필요.

## 3. 세계관

- **인류:** 전쟁 후 거점·요새 생존 단계
- **적:** 기원 불명, 거점 지속 공격, 질서·통제에 매몰
- **EXCELION:** 인류의 최후 공성 메카 / 수호자, 전투로 진화
- **테마:** 승리 서사보다 생존 서사
- 키워드(엑셀리온 README 쪽): 루프, 고대 문명(레무리아·아틀란티스 등) — WORLD.md에는 약함

**점검:** WORLD는 의도적으로 단순. 고대 문명·시즌(지구→태양계)은 README에만 있어 세계관 문서와 어긋남 → 통합 필요.

## 4. 스토리 · 갈등

| 축 | 내용 |
|----|------|
| 인류 | 불완전하지만 서로를 지킴 |
| 적 | 감정을 배제한 “완벽한 질서”, 존재 목적 상실 |
| 핵심 대립 | 질서 vs 생명·희망 |
| 파일럿 | 섬멸이 목적 아님, 전선·내일을 지키는 것 |
| 적 계급 | Drone → Assault → Fortress → Guardian(보스) → Sovereign(암시만) |

**점검:** 테마는 선명. 주인공·조연·시즌 플롯 본문은 설계 문서에 거의 없음(설정 스케치 수준).

## 5. 게임플레이 · 루프

```
Hangar → 정비 → 미션 선택 → 출격 → 전투 → 보스 → 보상 → 강화/진화 → 다음 미션
```

- 미션 예: 거점 방어, 기지 파괴, 호위, 거대 병기 요격
- 보상: 자원·부품·데이터·무장·진화
- 실패: 일부 성장 유지, 재도전 유도

**점검:** 루프·GAMEPLAY·GAME_LOOP 일치. Prototype은 이 루프 한 바퀴만으로 재미 검증이 목표.

## 6. 전투 디자인

| 요소 | 방향 |
|------|------|
| 이동 | 무겁지만 둔하지 않음 — 대시·부스트·회피 |
| 시점 | 3인칭, 메카가 멋져 보이는 카메라 |
| 락온 | 기본, 보스전 핵심 |
| 주력 | 원거리(메가 캐논 + 보조) |
| 근접 | 마무리·긴급·연출 |
| 자원 | Heat / Overdrive |
| 보스 | 약점·패턴·파괴 부위·피니시 연출 |

Prototype 최소: 이동·카메라·락온·대시·메가 캐논·Heat·보스 1·피니시.

**점검:** 전투 문서가 가장 구현에 가깝게 쪼개져 있음. 실코드(UE)는 깃에 없음.

## 7. 기체 · 비주얼 디자인

- Brave → 개량 → 강화 → Exelion → Exelion Empress (성장 라인)
- 약 25m, 인간형, 여성형 실루엣이되 노출·섹시함보다 강인·품위·수호자
- 키워드: 90년대·Retro·Imperial·곡선, 초기 단순 → 성장 시 장식 증가
- 레퍼런스: Gunbuster, Getter, Gurren, FSS 등
- S-Core = 심장/동력 — 정체는 “이후 정의”로 열림

**점검:** 정체성 문서는 강함. S-Core·진화 단계의 게임 규칙(언제/조건)은 아직 약함.

## 8. 톤 · 플레이어 감정 (목표)

압도감 · 긴장 · 성장 · 성취 · 수호 책임 · (피니시 시) 카타르시스

→ “강한 메카를 조종했다”보다 “끝까지 싸워 해냈다.”

## 9. 문서 구조상 위치

| 내용 | 주로 |
|------|------|
| 게임 기획·설계 | `projects/excelion-forge/docs/` (VISION~COMBAT, design/) |
| 프로젝트 헌장·백로그 | `projects/excelion/` |
| 제작 도구 | 같은 레포의 Forge 애드온 (기획과 혼재) |

**점검:** 기획 Bible이 excelion-forge/docs에 있어 “Forge=툴, Excelion=게임” 경계와 어긋남. 장기적으로 excelion/docs로 옮기거나 INDEX만 게임 쪽으로 두는 편이 맞음.

## 10. 기획 점검 요약 (갭)

| 잘 된 점 | 보완 권장 |
|----------|-----------|
| 장르·루프·전투 우선순위 명확 | 시즌/고대문명 vs 단순 WORLD 통합 |
| 적 철학·대비 선명 | 스토리 아크·캐릭터(파일럿) 문서화 |
| 메카 정체성·연출 강조 | S-Core·진화의 플레이 규칙 |
| 1인·출시·재사용 원칙 | Charter AI 역할(Sera) D19 반영 |
| Prototype 범위 잘 잘림 | UE 쪽 구현 증거는 깃 밖/미존재 |

## 한 줄

엑셀리온은 거점을 지키는 공성 메카의 미션 액션이고, 문서는 감정·루프·전투·IP까지는 정합적이다. 약한 쪽은 상세 스토리·S-Core 규칙·세계관 확장의 단일 출처와, 기획 문서가 Forge 폴더에 섞여 있는 구조이다.
