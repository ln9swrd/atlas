## 한 줄 결론

기획의 **뼈대는 1인 개발에 맞다.**  
그러나 **문서·도구에 비해 플레이 가능한 최소 단위가 아직 없다.**  
다음 단계는 “더 좋은 기획”이 아니라 **Prototype 수치·보스 1기·플레이 빌드**다.

---

## 잘 된 점 (1인 개발에 유리)

| 항목 | 평가 |
|------|------|
| **장르 범위** | Mission-Based 3D Action. 오픈월드·RPG·크래프팅 배제. 1인에 맞음 |
| **Prototype 범위** | 이동·락온·메가캐논·Heat·적1·보스1·미션1. 잘 잘림 |
| **전투 우선** | 스토리/세계관보다 전투 재미 검증을 먼저 둠. 올바른 순서 |
| **재사용 원칙** | 맵·적·시스템 재사용 명시. 1인 생존 전략 |
| **Do Not Build** | 만들지 않을 목록이 명확. 범위 폭주 방지 |
| **메카 정체성** | 여성형+강인, 성장 라인, 레퍼런스 명확. IP로 가져가기 좋음 |

→ 방향과 범위 설정은 1인 개발에 적합하다.

---

## 문제가 되는 점 (1인 기준 위험)

### 1. 문서 과다 · 구현 부재
기획 문서가 매우 많다. 반면 Unreal 쪽 플레이 가능 증거는 거의 없다.  
1인은 **문서보다 플레이 가능한 빌드**가 먼저다.

### 2. 세계관 불일치
- `WORLD.md` = 단순 생존
- README = 고대 문명·루프·시즌(지구→태양계)

→ Prototype에는 단순 WORLD만 쓰고, 확장은 나중으로 미뤄야 한다.

### 3. 핵심 규칙이 비어 있음
- S-Core / 진화: 조건·타이밍·조작 변화 없음
- 보스 1기: 패턴·약점·수치 없음
- Heat/Overdrive: 개념만 있고 숫자 없음

→ Prototype 구현 시 바로 막히는 부분.

### 4. 파이프라인 도구 vs 게임 본편
Forge(Blender 애드온)에 에너지가 많이 가고 있다.  
1인 기준으로는 **게임 재미 검증(Prototype)** 이 도구 완성보다 앞이다.  
도구는 “지금 당장 필요한 최소 검증(Rig Validator 등)”만 하고, 나머지는 Prototype 이후.

### 5. 스토리·파일럿
테마는 선명하나 주인공·동기·미션 연결이 거의 없다.  
Prototype에는 1줄 스토리 + 파일럿 최소 설정이면 충분. 지금은 과투자 영역이 아님.

## 1인 관점 권장 순서 (기획 마무리 기준)

1. 세계관: Prototype용으로 **단순 WORLD만 채택** (고대문명·시즌은 보류)
2. Prototype 스토리 1줄 + 파일럿 최소
3. 보스 1기 패턴·약점·체력 초안
4. Heat / 메가캐논 수치 초안
5. Unreal에서 이동+락온+사격만 돌아가는 빌드
