### PROPOSAL
* **ABP Structure** – An *Attack Slot* (or dedicated Attack State) that plays an Animation Montage/Sequence when the BP variable `bIsAttacking` is true.
  * The slot should be placed *after* the Locomotion state machine so that locomotion continues during the attack.
  * If a full‑body attack is required, a separate *Attack State* that overrides locomotion can be used.
  * For upper‑body attacks, a *Layered Blend Per Bone* or *AnimLayer* that blends the attack on upper‑body bones while preserving the locomotion pose is preferable.
  * The slot or state must expose an *output pose* that feeds into the final `Blend` node used for rendering.
* **Animation Asset** – One non‑looping humanoid Animation Sequence/Montage that lasts ~0.4 s (matching `AttackDuration`).  The root motion can be disabled; the animation should contain the clear hit‑moment around 0.15 s so the C++ `DamageWindowStart` aligns with the visual impact.

### C++ 변경 필요성
REQUIRED / UNVERIFIED – The current C++ logic already sets and clears the `bIsAttacking` flag and tracks timing.  No additional C++ code is required to trigger animation playback, provided the BP exposes the flag and the BP’s event graph or animation graph uses it.  Therefore, **NOT REQUIRED**.

### ABP 변경 필요성
REQUIRED – To actually play an attack animation the BP must expose a flag that can be read by the AnimGraph (or Event Blueprint) and must have a slot or state that plays the animation.  Hence **REQUIRED**.

### Animation Asset 필요량
Attack Animation = **1종** (non‑looping, ~0.4 s, humanoid, retargetable to `SK_Player_Axion_Skeleton`).

### Full Body vs Upper Body
* **Full Body** – Simpler to implement: one state that overrides locomotion and plays the entire body animation.  Requires a clean blend back to locomotion when the state ends.
* **Upper Body** – More flexible; preserves locomotion during attack and allows mixing other body movements.  Needs a *Layered Blend Per Bone* or *AnimLayer* to isolate the upper‑body bones.
**Recommendation:** Start with **Upper Body** using a dedicated *Attack Slot* that blends on the upper‑body bones.  If the game design requires the entire body to be immobilized, switch to a full‑body attack state.
