### 후보 구조 비교
#### 후보 A — Full Body Montage
```
Locomotion State Machine → Attack Montage (full body) → Transition back to Locomotion
```
* **Pros**: Simplest state transition; no need for layered blending.
* **Cons**: Requires a dedicated Attack State; may affect locomotion if not properly timed.

#### 후보 B — Upper Body Montage via Slot
```
Locomotion State Machine
   ↓
Upper Body Slot (Layered Blend Per Bone)
   ↓
Attack Montage (upper body only)
```
* **Pros**: Locomotion continues; minimal impact on full body pose.
* **Cons**: Requires proper Slot and Layered Blend setup; more complex to maintain.

### Attack Timing 연결
* **AttackDuration (0.40 s)** should match Montage length.  If Montage is longer, play rate can be adjusted.  If shorter, the `AttackDuration` may be extended or idle padding added.
* **DamageWindowStart (0.15 s)** should align with an Animation Notify or a keyframe marking the impact.  The Montage should expose a Notify at this timestamp.

### `bIsAttacking` 사용 방식
* **Method A (State Switch)** – Use `bIsAttacking` as a boolean to drive a transition from Locomotion → Attack State.  This requires adding a new state in the AnimGraph and a transition rule based on the variable.
* **Method B (Layered Blend)** – Keep Locomotion active and blend the Attack Montage into the upper body via a Slot.  `bIsAttacking` controls the visibility of the Slot.
* **Recommendation** – Method B minimizes state changes and is less likely to disrupt locomotion flow, especially if the game design emphasizes continuous movement during attack.

### 최소 변경안 확정
**CONFIRMED** – The minimal, most conservative approach is to
1. **Add an Upper Body Slot** named `AttackSlot` in the AnimGraph, attached to the **Layered Blend Per Bone** node that targets the **Chest** (or **Spine_01**) bone.
2. **Create an Attack Montage** (single‑shot, 0.40 s) that plays the imported Attack Animation.  The Montage should have an **Anim Notify** at 0.15 s for damage application.
3. **Expose a boolean variable** `bIsAttacking` in the ABP.  When `IsAttacking()` returns true, the `AttackSlot` is activated; otherwise it is muted.
4. **No additional states** are required; the Locomotion state machine remains unchanged.

This structure requires only the addition of a Slot, a Montage, and a Notify.  All other logic (C++ `bIsAttacking`, timers, damage window) remains untouched.
