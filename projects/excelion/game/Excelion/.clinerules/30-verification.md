# Excelion Verification Rules

## 5. PASS의 정의

다음 조건을 만족하지 않으면 PASS라고 보고하지 않는다.

### 입력

W → 실제 전진
S → 실제 후진
A → 실제 좌측 이동
D → 실제 우측 이동

### 회전

Mouse X → 예상된 좌우 시점 변화
Mouse Y → 예상된 상하 시점 변화

### 게임플레이

공격 → 실제 공격 발생
피격 → 실제 피격 발생
Victory → 실제 승리 상태
Defeat → 실제 패배 상태
Retry → 실제 재시작
Level Travel → 실제 레벨 이동

"이벤트가 발생했다"만으로 PASS하지 않는다.

반드시 최종 사용자 행동 결과를 확인한다.


## 10. 테스트와 검증

빌드 성공은 기능 성공이 아니다.

컴파일 성공 ≠ 실행 성공
실행 성공 ≠ 기능 성공
이벤트 발생 ≠ 올바른 결과

최종 검증은 실제 사용자 행동 기준으로 수행한다.


## 11. 기존 검증 결과 처리

기존 Agent의 PASS/COMPLETE 보고는 참고자료일 뿐이다.

현재 실행 결과와 충돌하면 현재 실행 결과를 우선한다.

충돌이 발생하면 다음을 조사한다.

- 테스트가 실제로 실행되었는가?
- 테스트 환경과 사용자가 실행한 환경이 같은가?
- 테스트가 실제 사용자 행동을 검증했는가?
- 자동 테스트가 실제 결과를 검증했는가?
- 설정 변경 후 테스트가 다시 실행되었는가?
