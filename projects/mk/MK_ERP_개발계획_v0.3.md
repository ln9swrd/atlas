## 4. 미완성 핵심 기능
### F-01 수주 다품목
현재 수주 문서가 사실상 단일 상세 처리에 묶여 있는 경로가 존재한다.
목표: 하나의 수주 문서에 여러 품목 상세행을 저장·조회·출고할 수 있어야 한다.
성공조건: 문서 1건에 2개 이상 품목을 등록하고 각각 부분출고/잔량출고 가능.

### F-02 발주 다품목
목표: 하나의 발주 문서에 여러 품목 상세행을 저장·조회·입고할 수 있어야 한다.
성공조건: 2개 이상 품목의 부분입고와 잔량입고가 독립적으로 처리된다.

### F-03 출고 Lot 지정
현재 수주 출고 처리에서 Lot 선택이 충분히 연결되지 않았다.
목표: 실제 출고 수량을 어떤 MK Lot/거래처 Lot에서 출고했는지 기록한다.
성공조건: 여러 Lot 보유 재고에서 지정 Lot별 출고 이력이 남고 Lot 잔량이 정확하다.

### F-04 입고 Lot 지정
목표: 실제 구매입고 수량에 Lot을 지정하고 입출고 원장에 보존한다.
성공조건: 한 발주 입고에 여러 Lot을 입력할 수 있고 Lot별 재고가 정확하다.

### F-05 Lot별 재고
현재 재고 조회의 핵심이 품목 단위에 머물러 있다.
목표: 품목 → MK Lot → 거래처 Lot 단위의 현재고와 이력을 조회한다.
성공조건: 전체 품목재고 합계와 Lot별 재고 합계가 일치한다.

### F-06 생산 Lot
목표: 생산실적/생산입고에 Lot을 연결한다.
성공조건: 생산입고된 수량이 지정 Lot으로 추적되고 Lot 재고에 반영된다.
## 5. 미완성 업무 기능
### F-07 수주/발주 문서 수정
목표: DRAFT 상태에서 상세행·수량·단가 등을 수정할 수 있다.
제약: CONFIRMED/CANCELLED 문서는 일반 수정 금지.
성공조건: 수정 전후 값이 감사 이력으로 추적된다.

### F-08 처리 이력 상세
목표: 수주 출고/발주 입고의 각 처리 이벤트를 날짜·수량·Lot·입출고 문서와 함께 조회한다.
성공조건: 부분 처리 2회 이상 발생 시 각 이벤트와 누계가 구분된다.

### F-09 문서 상세 조회
목표: 목록에서 문서를 선택하면 헤더와 모든 상세행, 처리량, 잔량, 단가 snapshot, Lot 이력을 확인한다.
성공조건: 문서 단위 업무 확인에 별도 DB 조회가 필요 없다.

### F-10 판매 취소 검증
기존 출고를 취소할 때 현재고 부족을 이유로 취소를 막지 않도록 로직을 수정했다.
남은 작업: 실제 출고→재고소진→취소→역입고 시나리오를 Runtime에서 검증한다.
성공조건: 취소 시 원 출고는 CANCELLED, 실제 처리수량만 역입고되고 이력이 연결된다.

### F-11 구매 취소 검증
입고 후 재고가 이미 사용된 경우 역출고 가능 여부와 부족재고 정책을 명확히 검증한다.
불명확한 정책은 자동 결정하지 않고 HOLD한다.
## 6. 기준정보/단가 강화
### F-12 단가 충돌 검증
목표: 동일 거래처·품목에 여러 단가가 존재할 때 적용일/우선순위 규칙을 정확히 적용한다.
성공조건: 기준일을 바꾸어도 예상 단가가 deterministic하게 선택된다.

### F-13 수주 단가 snapshot 검증
목표: 수주에 실제 적용된 단가를 보존한다.
성공조건: 이후 기준단가 변경에도 기존 수주 금액이 변하지 않는다.

### F-14 문서번호 규칙 검증
목표: 수주/발주/입출고/생산 번호가 설정 저장소의 규칙으로 생성된다.
성공조건: 재실행 후에도 중복 없는 번호가 생성된다.

### F-15 설정값 하드코딩 점검
목표: 변경 가능한 업무 코드/상태/유형/번호 규칙이 소스에 하드코딩되지 않았는지 최종 점검한다.
성공조건: 설정 저장소에서 조회·변경 가능한 값은 코드 수정 없이 반영된다.

## 7. 재고·원장 강화
### F-16 초기재고 Runtime 검증
초기재고가 직접 현재고를 수정하지 않고 Transaction으로 기록되는지 확인한다.

### F-17 입출고 원장 정합성
수주/발주/생산/LOSS/조정의 모든 재고 변화가 독립 원장으로 남는지 확인한다.

### F-18 취소 역거래 정합성
취소 시 원 거래를 물리 삭제하지 않고 CANCELLED 처리하며 역거래를 생성하는지 확인한다.

### F-19 재고 계산 정합성
초기재고 + 기간 입고 - 기간 출고 - LOSS ± 조정 = 현재고 관계를 검증한다.
## 8. 출력·운영 기능
### F-20 Excel 전 화면 점검
주요 업무 조회 화면에서 현재 필터/선택 결과가 Excel로 정확히 나오는지 확인한다.

### F-21 인쇄 점검
주요 문서와 조회 결과의 인쇄 레이아웃, 한글, 페이지 분할을 확인한다.

### F-22 백업/복구

복구 전 현재 DB의 안전 백업이 생성되어야 한다.

### F-23 감사 이력
등록/수정/취소/가격변경/재고조정의 사용자·일시·대상·변경 전후 값 추적 범위를 확인한다.

### F-24 Stand-alone 배포
현재 ZIP은 실행 검증되었다.
남은 작업: 새 PC/깨끗한 환경을 가정한 설치·실행·DB 초기화·데이터 저장 경로 검증.
Installer는 별도 결정 사항이며 현재 범위에서는 자동 착수하지 않는다.
## 9. 통합 검증 시나리오
### T-01 기준정보
거래처 등록 → 품목 등록 → 거래처-품목 연결 → 단가 2개 이상 등록.

### T-02 단가
적용일/우선순위에 따라 자동 선택 → 수주에서 수동 수정 → 수주 저장 → 기준단가 변경 → 기존 수주 금액 불변 확인.

### T-03 수주
다품목 수주 → 확정 → 품목별 부분출고 → 잔량출고 → 재고와 처리량 확인.

### T-04 수주 취소
출고 완료 → 해당 재고 일부 소진 → 수주 취소 → 역입고 → 원 출고 CANCELLED 및 이력 확인.

### T-05 발주
다품목 발주 → 확정 → 품목별 부분입고 → 잔량입고 → 재고와 처리량 확인.

### T-06 발주 취소
입고 완료 → 일부 재고 사용 → 취소 시 정책에 맞는 역출고 및 오류 처리를 검증한다.
정책이 불명확하면 HOLD.

### T-07 생산
생산실적 → 생산입고 → 불량수량 LOSS → Lot별 재고 확인.

### T-08 Lot
한 문서에 2개 이상 Lot 입력 → 저장 → Lot별 이력 → Lot별 재고 → 품목 전체 재고 합계 대조.

### T-09 운영
Excel → 인쇄 → 감사 이력 → 백업 → 복구 → 재실행 확인.

## 11. 작업 규칙
1. 각 Phase 시작 전에 HEAD/Branch/Working Tree를 확인한다.
2. 기존 변경사항은 보존한다.
3. 조사 단계는 READ-ONLY를 기본으로 한다.
4. 한 번에 하나의 핵심 변수를 변경한다.
5. 수정 후 Diff를 확인한다.

## 14. Phase A 결정 게이트
### DG-01 수주/발주 상세행과 입출고 상세의 연결
현재 TB_INOUT_DETAIL은 품목 및 Lot을 보유하지만 수주/발주의 상세행 ID를 직접 보유하지 않는다.
단일 품목 문서에서는 품목 기준으로 처리 경로를 구성할 수 있으나, 다품목 문서에서 동일 문서의 각 상세행별 부분출고/부분입고/취소 이력을 정확히 추적하려면 원천 상세행 식별자가 필요하다.

현재 확인된 선택지:
- A: TB_INOUT_DETAIL에 SOURCE_DETAIL_ID와 SOURCE_DETAIL_TYPE을 추가하여 원천 상세행을 직접 연결
- B: 품목 및 문서 ID 조합으로 간접 추적하고 동일 품목의 중복 상세행을 제한
- C: 수주/발주 처리 구조를 별도 처리 이력 테이블로 확장

현재 상태:
- A/B/C 중 Master 결정 전 구현하지 않음.
- 임시로 UI만 다품목화하지 않음.
- 기존 Working Tree 변경사항은 보존함.

판정: HOLD
이유: 다품목 업무의 부분처리와 취소 이력 정합성에 직접 영향을 주는 설계 결정 필요.

## 15. DG-01 결정 결과 — C안 확정

### 확정 구조

- 기존 단일상세 수주/발주 처리: 신규 처리부터 이력 생성
- 취소: 역입출고와 처리이력을 `REVERSE`로 기록
- 기존 데이터: 원천 상세행을 품목 기준으로 유일하게 식별할 수 있는 경우에만 보강
