# MK ERP Canon v0.1
## 1. 목적
이 문서는 Master가 승인한 MK ERP의 불변 업무·기술 원칙을 기록한다.
PROPOSAL은 Master 승인 전까지 Canon이 아니다.

## 2. Canon 목록
### C-001 설정값 저장소 원칙
설정값을 소스 코드에 하드코딩하지 않는다.
기준정보, 업무 코드, 상태값, 유형값, 변경 가능한 프로그램 설정값은 설정/기준정보 저장소에서 조회하여 사용한다.
초기 기본값이 필요하면 설치 또는 초기화 과정에서 저장소에 등록한다.
소스 코드에는 조회·검증·적용 로직을 두며 변경 가능한 업무값 자체를 하드코딩하지 않는다.

### C-002 문자 인코딩 원칙
MK ERP의 소스 코드와 문서는 UTF-8 인코딩을 사용한다.
파일 입출력과 데이터 처리에서도 UTF-8을 기본으로 하여 한글 및 다국어 문자가 깨지지 않도록 한다.

### C-003 업무 데이터 실제 삭제 금지
업무 데이터는 실제 삭제하지 않는다.
오류 데이터는 취소·무효화·정정 등의 상태와 이력으로 관리한다.
DB의 물리적 삭제는 일반 업무 기능으로 제공하지 않는다.

### C-004 초기재고 Transaction 원칙
초기재고는 별도의 재고 숫자를 직접 유지하는 방식이 아니라 초기재고 Transaction으로 등록한다.
재고는 초기재고와 이후 거래 Transaction을 기반으로 계산한다.

### C-005 Lot 직접입력 원칙
MK Lot No와 거래처 Lot No는 사용자가 직접 입력한다.
자동 Lot 번호 생성은 사용하지 않는다.
두 값 모두 업무용 식별자이며 DB PK와 분리한다.

### C-006 Lot 관계 원칙
MK Lot과 거래처 Lot은 양방향 다대다 관계를 허용한다.
하나의 MK Lot에 여러 거래처 Lot이 연결될 수 있고, 하나의 거래처 Lot이 여러 MK Lot과 연결될 수 있다.
동일 거래처의 동일 Lot은 중복 입력을 허용한다.
품목을 사용자가 완벽하게 구분하지 못하는 업무 현실을 고려하여 Lot 입력을 과도하게 제한하지 않는다.

### C-007 입출고 원장 독립 원칙
입출고 내역은 수주·생산실적과 독립된 재고 원장으로 관리한다.
수주 또는 생산실적의 업무 처리가 필요한 경우 입출고 Transaction이 생성되어 재고에 반영된다.
수주 자체나 생산실적 자체를 재고 원장으로 사용하지 않는다.

### C-008 단가 수동 수정 허용
기준 단가는 거래처와 품목 및 적용기간을 기준으로 자동 조회한다.
사용자는 수주 등 거래 입력 과정에서 조회된 단가를 수동 수정할 수 있다.
실제 적용 단가는 거래 문서에 보존하여 기준 단가 변경이 과거 거래에 영향을 주지 않게 한다.

### C-009 문서번호 자동 생성
수주·발주·입출고·생산 등 문서번호는 시스템이 규칙에 따라 생성한다.
문서번호 규칙 자체는 변경 가능한 업무 설정으로 취급하며 소스 코드에 하드코딩하지 않는다.

### C-010 백업 정책
데이터는 주 1회 Full Backup을 수행한다.
복원 실행 전에는 현재 데이터베이스를 별도 안전 백업한다.
백업 보존기간은 별도 운영 설정으로 관리한다.

### C-011 감사·변경 이력
중요 업무 데이터는 변경 추적이 가능해야 한다.
최소한 등록, 수정, 취소, 재고조정, 가격변경, 주요 기준정보 변경을 추적한다.
가능한 범위에서 사용자, 일시, 대상 데이터, 이전 값, 변경 후 값을 보존한다.

### C-012 UTF-8 및 저장소 원칙 적용
C-001과 C-002는 설계, 구현, 테스트, 배포 문서 전체에 적용한다.

### C-013 발주 취소 재고 부족 처리
입고가 발생한 확정 발주를 취소할 때 이미 사용된 재고가 있으면 취소 자체를 차단하지 않는다.
현재 Lot별 잔여 재고 범위에서 가능한 수량은 역출고(OUT)로 처리한다.
역출고할 재고가 부족한 수량은 별도의 재고조정(ADJUST) Transaction으로 기록하며, 해당 조정은 부족 수량만큼 재고를 감소시키는 signed quantity로 저장한다.
원 발주 문서는 CANCELLED로 변경하고, 역거래 및 재고부족 조정의 원천관계와 감사이력을 보존한다.
## 3. Canon 적용 우선순위
1. Master가 명시적으로 승인한 Canon
2. 현재 프로젝트의 확정 요구사항
3. 설계안 및 개발계획의 PROPOSAL
4. 구현 단계의 기술적 PROPOSAL

하위 문서의 내용이 Canon과 충돌하면 Canon을 우선한다.

## 4. 변경 원칙
Canon 변경은 Master 승인 없이 수행하지 않는다.
구현 중 Canon과 충돌하는 요구나 기존 데이터 문제가 발견되면 자동 수정하지 않고 HOLD로 보고한다.
