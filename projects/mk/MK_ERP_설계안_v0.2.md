# MK ERP 설계안 v0.2

## 1. 문서 목적
본 문서는 Master가 확정한 MK ERP 요구사항과 현재 설계를 종합한다.
대상은 인터넷 없이 일반 Windows PC에서 1인이 사용하는 Stand Alone ERP다.
현재 업무에 필요한 최소 기능을 우선 구현하고 확장 가능한 RDB 구조를 유지한다.

## 2. 핵심 업무
- 수주관리
- 발주관리
- 생산실적관리
- 입고관리
- 출고관리
- LOSS 관리
- 재고현황 및 재고조정
- 품목/등급 관리
- 거래처/거래처별 품목 관리
- Lot 관리 및 추적
- 단가 관리
- 데이터 사전 및 설정 관리
- 보고서, 인쇄, PDF, Excel
- 백업 및 복원
- 감사/변경 이력

## 3. 확정 업무 원칙
- 업무 데이터 실제 삭제 없음.
- 재고는 Transaction으로 계산한다.
- 초기재고도 초기재고 Transaction으로 기록한다.
- 입출고 원장은 독립적으로 관리한다.
- 수주/생산 처리 결과가 필요한 경우 입출고 Transaction을 생성한다.
- LOSS는 별도 재고감소 유형이다.
- MK Lot No와 거래처 Lot No는 사용자가 직접 입력한다.
- Lot은 MK Lot ↔ 거래처 Lot의 N:M 관계를 허용한다.
- 같은 거래처의 같은 Lot 중복 입력을 허용한다.
- 수주 단가는 자동 조회 후 수동 수정 가능하다.
- 거래 시점의 실제 적용 단가를 문서에 보존한다.
- 문서번호는 규칙에 따라 자동 생성한다.
- 변경 가능한 업무 설정은 저장소에서 조회하며 하드코딩하지 않는다.
- 소스 코드와 문서는 UTF-8이다.
- 백업은 주 1회 Full Backup을 기본으로 한다.
- 중요 데이터의 변경 이력을 추적한다.

## 4. 업무 데이터와 재고 원장
수주, 발주, 생산실적은 업무 문서이고 입출고는 재고 원장이다.
업무 문서가 생성되었다는 사실만으로 재고를 변경하지 않는다.
실제 입고/출고 처리 시점에 입출고 Transaction을 생성한다.
## 5. 수주 및 출고
수주 Header:
- 수주번호
- 수주일
- 거래처
- 납기일
- 담당자
- 상태
- 비고

수주 Detail:
- 품목
- 거래처 품번
- 수량
- 단가
- 금액
- 납기일
- 비고

수주 입력 시 거래처+품목 기준 단가를 조회한다.
조회 단가는 사용자가 수정할 수 있다.
최종 적용 단가는 수주 상세에 저장한다.
수주와 출고는 분리한다.
출고 처리 시 실제 출고 수량만 입출고 원장에 반영한다.
부분출고는 허용하는 방향으로 설계하되 상세 업무 규칙은 구현 전 검증한다.

## 6. 발주 및 입고
발주 Header:
- 발주번호
- 발주일
- 거래처
- 납기일
- 상태
- 비고

발주 Detail:
- 품목
- 수량
- 단가
- 금액
- 납기일
- 비고

발주와 입고는 분리한다.
실제 입고 처리 시 입출고 원장에 구매입고 Transaction을 기록한다.
부분입고 가능성을 고려하여 잔량을 계산할 수 있는 구조로 한다.

## 7. 생산
생산은 생산실적 중심으로 관리한다.
- 생산일
- 생산 품목
- 생산수량
- 불량수량
- 비고

생산실적과 재고 원장을 분리한다.
생산 완료 처리 시 제품 생산입고 Transaction을 생성하는 구조를 사용한다.
필요한 원재료 사용은 별도의 입출고 Transaction으로 기록한다.
BOM, MRP, 생산계획, 작업지시, 공정, WIP, 생산원가 계산은 1차 범위에서 제외한다.

## 8. 입출고
입출고는 독립 원장이다.
최소 유형:
- 초기재고
- 구매입고
- 생산입고
- 반품입고
- 납품출고
- 생산출고
- 반품출고
- LOSS
- 재고조정
- 기타

실제 유형과 증감 방향은 데이터 사전/설정 저장소에서 관리한다.
업무 코드와 유형을 소스에 하드코딩하지 않는다.

## 9. 재고
사용자가 현재고 숫자를 직접 수정하지 않는다.
재고조정도 조정 Transaction을 생성한다.
기본 개념은 기초 + 재고증가 Transaction - 재고감소 Transaction이다.
LOSS와 조정은 각각 원인과 유형을 추적한다.
Carrier의 생산일자는 거래일자와 별도 필드로 보존한다.

## 10. Lot
DB PK인 LOT_ID와 업무용 Lot 번호를 분리한다.
MK Lot No와 거래처 Lot No는 사용자가 입력한다.
Lot 관계는 N:M이다.
관계 테이블을 통해 이력을 추적한다.
동일 거래처+동일 Lot 입력은 허용한다.
Lot 입력 시 필수값과 기본 형식은 검증하되 업무 현실을 고려하여 과도한 품목 일치 제약은 두지 않는다.
## 11. 기준정보 및 설정 저장소
품목, 등급, 거래처, 거래처별 품목, 단가, 단위, 업무유형, 상태, 문서번호 규칙, 회사정보 등 변경 가능한 값은 저장소에서 관리한다.
소스 코드에 업무값을 하드코딩하지 않는다.
초기 기본값은 설치/초기화 과정에서 저장소에 등록한다.
기술적 불변 상수와 변경 가능한 업무 설정은 구분한다.

## 12. 감사/변경 이력
중요 데이터는 등록자/등록일시, 수정자/수정일시를 보존한다.
수정 및 취소가 중요한 업무 데이터는 변경 이력을 남긴다.
가격, 재고조정, 기준정보 등은 이전 값과 변경 후 값을 추적할 수 있게 한다.
실제 구현의 감사 대상과 보존 범위는 DB 설계 단계에서 구체화한다.

## 13. 백업/복원
주 1회 Full Backup을 기본 정책으로 한다.
백업 파일은 별도 위치에 보관한다.
복원 전에 현재 DB를 자동 백업한다.
백업 보존기간과 파일명 규칙은 설정 저장소에서 관리할 수 있도록 한다.
복원 후 DB 무결성 검증을 수행한다.

## 14. 보고서 및 출력
주요 화면은 Excel 내보내기를 제공한다.
Excel은 원장 DB가 아니라 분석/전달 수단이다.
인쇄물과 PDF는 업무 문서/보관/전달 용도로 분리한다.
주요 출력:
- 수주서
- 발주서
- 입고전표
- 출고전표
- 생산실적
- 재고현황
- Lot 추적현황
- 거래처별 거래현황
- 거래처별 단가현황

## 16. 식별자 원칙
DB PK는 내부 식별자로 사용한다.
업무번호와 업무용 Lot 번호는 별도 필드로 관리한다.
문서번호는 설정된 규칙에 따라 시스템이 생성한다.
Lot 번호는 사용자가 입력한다.
거래 당시 적용 단가 등 역사적 값은 거래 데이터에 Snapshot으로 보존한다.

## 17. UI 원칙
Excel 사용 습관을 고려한 표 중심 UI를 제공한다.
조회, 초기화, 신규, 저장, 취소, Excel, 인쇄 기능을 공통화한다.
사용자가 품목을 완벽하게 구분하지 못하는 업무 현실을 고려하여 검색과 선택을 쉽게 한다.
중요한 자동 생성/자동 계산 값은 사용자가 확인할 수 있게 한다.

## 18. 삭제 및 정정
일반 업무 화면에는 실제 삭제 기능을 제공하지 않는다.
잘못 입력한 데이터는 취소 또는 정정 절차로 처리한다.
이미 재고에 영향을 준 Transaction은 이력 손실 없이 반대/정정 Transaction 또는 취소 상태로 처리한다.
구체적인 정정 방식은 구현 시 원장 무결성을 기준으로 확정한다.

## 20. Windows 배포
최종 사용자는 별도 DB 서버나 개발환경 없이 실행할 수 있어야 한다.
프로그램 파일과 사용자 DB/백업 데이터를 분리한다.
설치 프로그램을 통해 필요한 구성요소를 배포한다.

## 21. 검토 결과 및 보류
현재 핵심 구조를 막는 미확정 사항:
- 문서번호의 구체적 문자열 형식
- 부분출고/부분입고의 세부 UI와 상태값
- 생산실적→입고 생성의 정확한 완료 조건
- 수량 단위별 소수점 정밀도
- 금액 반올림 규칙
- 가격 적용기간 충돌 시 선택 규칙
- 백업 보존기간
- 감사 로그의 상세 보존 범위
- Carrier '인상'의 정확한 의미
- SUS '각인확인'의 정확한 의미
- 생산일자 적용 범위
- 한 입고에서 여러 Lot을 입력하는 UI

위 항목은 DB 기본 구조를 파괴하지 않는 범위에서 구현 단계에서 확정할 수 있다.
핵심 구조와 충돌 가능성이 발견되면 HOLD한다.

## 23. 문서 상태
