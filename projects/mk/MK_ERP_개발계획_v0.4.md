## 4. 라이선스 정책 및 잔여 작업
### L-01 PC 귀속 정책
목표: 라이선스 1개를 특정 PC 1대에 귀속하고 다른 PC로 license.json을 복사해 재사용하는 것을 차단한다.
구현: MachineGuid, SMBIOS UUID, BaseBoard Serial, BIOS Serial, 시스템 물리 디스크 Serial의 5개 값을 개별 SHA-256 해시로 저장하고 3개 이상 일치하면 동일 PC로 인정한다.
Windows 재설치·시스템 디스크 교체 등 일부 환경 변경은 나머지 식별값이 3개 이상 유지되면 동일 PC로 인정할 수 있다.
기존 v1 MachineFingerprint 라이선스는 호환 검증 경로를 유지하고 신규 발급은 v2 하드웨어 바인딩만 허용한다.
상태: IMPLEMENTED / BUILD VERIFIED / Runtime binding VERIFIED.

### L-02 라이선스 서버 도입
현재 목적에는 필요하지 않다.
원격 활성화 수량 관리, 원격 회수, 중앙 블랙리스트가 필요해질 때 별도 요구사항으로 검토한다.
상태: OUT OF SCOPE.

### L-03 라이선스 보안 강화
실행 파일 패치까지 방지하는 DRM은 현재 범위에 포함하지 않는다.
DEBUG 빌드는 고객 배포 금지, 고객 배포물은 Release만 사용한다.
상태: 운영 규칙으로 관리.

### L-04 라이선스 예외 시나리오
Windows 재설치 등으로 일부 식별값이 변경되어도 5개 중 3개 이상이 유지되면 기존 라이선스를 계속 사용할 수 있다.
3개 미만으로 일치하는 경우는 신규 PC 또는 중대한 하드웨어 변경으로 간주하여 재발급 절차를 적용한다.
상태: 기술정책 구현 완료 / 고객 재발급 운영절차는 별도 문서화 필요.

## 5. 잔여 기능 개발 및 검증
### F-01 수주 다품목 Runtime 검증
2개 이상 품목 수주 → 확정 → 품목별 부분출고 → 잔량출고를 실제 실행한다.
성공조건: 상세행별 처리수량/잔량/입출고 이력이 서로 일치한다.

### F-02 발주 다품목 Runtime 검증
2개 이상 품목 발주 → 확정 → 품목별 부분입고 → 잔량입고를 실제 실행한다.
성공조건: 상세행별 처리수량/잔량/입출고 이력이 서로 일치한다.

### F-03 다중 Lot 출고 검증
하나의 품목에 여러 Lot을 준비하고 지정 Lot별 부분출고를 실행한다.
성공조건: 선택 Lot의 재고만 감소하고 Lot별 출고 이력이 남는다.

### F-04 다중 Lot 입고 검증
하나의 발주 입고에 2개 이상 Lot을 지정한다.
성공조건: Lot별 입고수량과 현재고가 정확하다.

### F-05 생산 Lot 검증
생산입고와 불량 LOSS에 Lot을 연결한다.
성공조건: 생산품 재고와 LOSS 원장이 동일 Lot 기준으로 추적된다.

### F-06 문서 수정 Runtime 검증
DRAFT 문서의 수량/단가/상세행을 수정하고 논리삭제 후 재조회한다.
성공조건: 확정 문서는 수정되지 않고 DRAFT 변경은 AuditLog에 남는다.

### F-07 처리 이력 상세 검증
동일 상세행에 부분처리를 2회 이상 수행한다.
성공조건: 각 처리 이벤트, 처리량, Lot, 입출고 상세, 누계가 구분된다.

### F-08 취소 역거래 검증
출고/입고 후 일부 재고가 사용된 상태에서 취소 정책을 실제 검증한다.
발주 취소는 C-013 정책에 따라 Lot별 가능한 수량은 역출고하고 부족분은 별도 재고조정으로 처리한다.
성공조건: 원거래는 CANCELLED, 가능한 역거래와 부족분 조정은 별도 원장으로 기록되며 원천관계와 이력이 보존된다.

### F-09 재고 정합성 검증
초기재고 + 입고 - 출고 - LOSS ± 조정을 실제 데이터로 대조한다.
성공조건: 품목 합계와 Lot 합계가 일치한다.

### F-10 백업/복구 검증
실제 DB를 백업하고 복구한 뒤 데이터와 애플리케이션 실행을 확인한다.
성공조건: 복구 전 안전 백업 생성, 복구 후 주요 업무 데이터 무결성 확인.

### F-11 Stand-alone 신규 PC 검증
깨끗한 Windows 환경을 가정하여 배포본 실행, 라이선스 검증, DB 초기화, 저장 경로를 확인한다.
성공조건: 정상 라이선스에서는 실행되고 무효/타 PC 라이선스에서는 실행되지 않는다.

### F-12 Excel/인쇄 검증
주요 목록과 문서를 실제 출력한다.
성공조건: 현재 필터/선택 결과, 한글, 페이지 분할이 정상이다.

## 6. 통합 검증 순서
### T-01 기준정보 → 단가
거래처/품목/거래처-품목/복수 단가 등록 후 적용일과 우선순위에 따른 단가 선택을 검증한다.

### T-02 수주
다품목 수주 → 확정 → 부분출고 → 잔량출고 → Lot/재고/처리이력 대조.

### T-03 수주 취소
출고 → 재고 일부 사용 → 취소 → 역입고 → 원거래 CANCELLED 및 이력 대조.

### T-04 발주
다품목 발주 → 확정 → 부분입고 → 잔량입고 → Lot/재고/처리이력 대조.

### T-05 발주 취소
입고 → 일부 재고 사용 → 취소 정책에 따른 역거래와 오류 처리를 검증한다.
정책이 불명확하면 HOLD한다.

### T-06 생산
생산실적 → 생산입고 → LOSS → Lot별 재고 및 원장 대조.

### T-07 운영
Excel → 인쇄 → 감사이력 → 백업 → 복구 → 재실행.

### T-08 라이선스
PC A 정상 라이선스 → 실행 성공.
PC B에 PC A license.json 복사 → 실행 거부.
PC B용 정상 라이선스 → 실행 성공.

## 8. 검증 상태 기준
- CODE VERIFIED: 실제 코드 경로 확인
- BUILD VERIFIED: 실제 Build 성공
- EDITOR VERIFIED: 실제 Asset/설정 확인
- PIE VERIFIED: 실제 Runtime 결과 확인
- NOT VERIFIED: 아직 실제 확인하지 않음

자동화 테스트 PASS는 PIE VERIFIED로 간주하지 않는다.
