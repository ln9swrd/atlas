# MK ERP 설계안
## 1. 문서 목적
본 문서는 현재까지 Master와 협의한 MK ERP의 요구사항과 1차 설계안을 정리한 기준 문서다.
인터넷 연결 없이 일반 Windows PC에서 혼자 사용하는 Stand Alone ERP를 목표로 한다.
현재 규모에 필요한 최소 기능을 우선 구현하고, 향후 확장은 구조적으로 가능하게 설계한다.
## 2. 시스템 목적
- 수주관리
- 발주관리
- 생산관리
- 입출고 관리
- 품목관리
- 거래처 관리
- 단가 관리
- 재고현황 관리
- 데이터 사전 관리
- 보고서 및 인쇄 지원
- 데이터 백업 및 복원
## 3. 기본 업무 흐름
거래처 / 품목 / 거래처별 품목 / 단가를 기준정보로 관리한다.
수주 등록 시 거래처와 품목을 기준으로 단가를 자동 조회한다.
필요한 경우 발주와 생산실적을 등록한다.
입고와 출고 거래를 기록한다.
재고는 입출고 Transaction을 기준으로 계산한다.
수주, 발주, 생산, 입출고, 재고 현황을 조회하고 인쇄한다.
## 4. 기준정보 - 품목
필수 정보:
- MK 품목코드
- 품목명
- 품목구분: 자재 / 반제품 / 제품
- 등급
- 규격
- 단위
- 사용여부
- 비고
품목ID와 업무용 MK 품목코드는 분리한다.
## 5. 기준정보 - 거래처
필수 정보:
- 거래처ID
- 거래처코드
- 거래처명
- 거래처 구분: 매입 / 매출 / 양쪽
- 사업자번호(필요 시)
- 대표자
- 주소
- 전화
- 담당자
- 사용여부
- 비고
## 6. 거래처별 품목
같은 품목이 거래처마다 다른 품번이나 품명을 가질 수 있으므로 별도 관계 데이터로 관리한다.
- 거래처
- 거래처 품번
- 거래처 품명
- MK 품목 연결
수주 입력 시 거래처 품번을 통해 MK 품목을 찾을 수 있도록 한다.
## 7. 단가관리
단가는 거래처 + 품목 + 적용기간을 기준으로 관리한다.
주요 항목:
- 거래처
- 품목
- 단가
- 단위
- 적용시작일
- 적용종료일
- 사용여부
- 비고
수주 입력 시 적용 가능한 단가를 자동 조회한다.
## 8. 수주관리
수주 Header:
- 수주번호
- 수주일
- 거래처
- 납기일
- 담당자
- 상태
- 비고
수주 Detail:
- 품목
- 거래처품번
- 수량
- 단가
- 금액
- 납기일
- 비고
금액은 수량 x 단가로 계산한다.
## 9. 수주-단가 연계
수주 입력 시 거래처와 품목을 기준으로 단가를 자동 조회한다.
수주에 실제 적용된 단가는 수주 상세에 별도로 저장한다.
따라서 이후 단가 Master가 변경되어도 과거 수주의 금액은 변경되지 않는다.
수주 화면에서 자동 단가의 수동 수정 허용 여부는 향후 업무 규칙으로 확정한다.
## 10. 발주관리
발주 Header:
- 발주번호
- 발주일
- 거래처
- 납기일
- 상태
- 비고
발주 Detail:
- 품목
- 수량
- 단가
- 금액
- 납기일
- 비고
필요한 경우 수주를 기준으로 발주를 생성할 수 있도록 확장 가능하게 한다.
## 11. 생산관리
현재 규모에서는 생산계획과 BOM을 넣지 않는다.
생산관리는 생산실적 중심으로 단순하게 운영한다.
주요 입력:
- 생산일
- 생산 품목
- 생산수량
- 불량수량
- 비고
생산 완료 시 제품 생산입고를 통해 재고에 반영한다.
필요한 원재료 투입은 입출고 거래로 관리한다.
## 12. 생산관리 제외 범위
1차 범위에서 다음은 제외한다.
- BOM
- MRP
- 생산계획
- 작업지시
- 공정관리
- 공정별 재공관리
- 생산능력계획
- 생산원가계산
향후 필요성이 확인되면 별도 모듈로 확장한다.
## 13. 입출고 관리
입출고는 재고의 핵심 Transaction이다.
입출고 구분값을 반드시 관리한다.
예:
- 구매입고
- 생산입고
- 반품입고
- 납품출고
- 생산출고
- 반품출고
- 폐기
- 기타
구분값은 데이터 사전에서 관리한다.
## 14. 재고관리
재고를 사용자가 임의 숫자로 직접 관리하지 않는다.
입출고 Transaction을 기준으로 재고를 산출한다.
기본 계산:
기말재고 = 기초재고 + 기간입고 - 기간출고
재고현황에는 기초, 입고, 출고, 기말을 표시한다.
필요하면 입출고 유형별 상세 집계도 제공한다.
## 15. 사용자 입력
최초 구축 시:
- 품목
- 거래처
- 거래처별 품목
- 단가
- 초기재고
일상 업무:
- 수주
- 발주
- 생산실적
- 입출고
필요 시:
- 기준정보 수정
- 재고조정
- 데이터 사전 추가
## 16. 자동 처리 대상
가능하면 사용자가 직접 입력하지 않도록 한다.
- 문서번호
- 금액
- 단가 자동조회
- 기초재고
- 입고 합계
- 출고 합계
- 기말재고
- 등록일시
- 수정일시
- 일부 상태값
## 17. 데이터 사전
프로그램에 업무 코드를 하드코딩하지 않고 데이터 사전으로 관리한다.
예:
- 품목구분
- 품목등급
- 단위
- 거래처구분
- 수주상태
- 발주상태
- 생산상태
- 입출고구분
기본값은 프로그램에서 제공하고 필요한 경우 사용자가 추가/수정할 수 있도록 한다.
## 18. RDB
1차 RDB는 SQLite를 사용한다.
이유:
- 별도 DB 서버 불필요
- 인터넷 불필요
- Stand Alone에 적합
- 하나의 DB 파일로 관리 가능
- 트랜잭션 지원
- 소규모 데이터에 충분
단, 애플리케이션이 SQLite에 직접 종속되지 않도록 DB 접근 계층을 분리한다.
## 19. 애플리케이션 구조
권장 구조:
UI
↓
Service
↓
Repository / DAO
↓
SQLite
UI와 업무 규칙, DB 접근을 분리하여 향후 PostgreSQL 등 서버형 RDB로 확장할 수 있도록 한다.
## 20. Windows 배포
최종 사용자는 별도의 DB, Runtime, 개발환경을 설치하지 않아도 되도록 한다.
권장 배포 방식은 설치 프로그램(MK_ERP_Setup.exe)이다.
설치 과정에서 필요한 Runtime과 SQLite 구성요소를 함께 제공한다.
사용자 데이터와 프로그램 파일은 분리한다.
예:
C:\Users\사용자\AppData\Local\MKERP\MKERP.db
