# MENOS 2D Art Direction and Entity Design Sheets

상태: **디자인 기준 초안**. 기존 기획/코드에서 확인한 역할은 `CONFIRMED`, 외형·팔레트·크기·애니메이션 표현은 `PROPOSAL`이다. 이 문서는 제작 지침 초안이며 Master 승인 전까지 시각 Canon으로 취급하지 않는다.

## 1. 기준과 근거

### CONFIRMED

- MENOS는 슈퍼로봇이 기지를 방어하는 전략형 Tower Defense다. 로봇이 중심 캐릭터이고 Tower는 기지 방어 수단이다.
- 플레이어는 로봇을 직접 조종하지 않고 출격과 위치를 지시한다. 로봇은 자동으로 적을 탐색하고 공격하며 능력을 사용한다.
- 현재 PoC 개체는 Robot 1종, Enemy 4종(Normal, Rusher, Heavy, Giant), Tower 2종(Cannon, Gatling)이다.
- Cannon은 Heavy/Giant를 선호하는 단발 화력 Tower, Gatling은 Normal/Rusher를 선호하는 빠른 연사 Tower다. 현재 코드의 선호 대상 탐색은 우선순위 방식이며, 선호 대상이 없으면 사거리 내 다른 적을 선택할 수 있다.
- Giant는 현재 적 중 가장 높은 HP를 가진 위협이며 Robot을 직접 공격할 수 있다. Heavy Pierce는 유효한 Heavy/Giant 대상만 공격한다.
- Godot PoC는 외부 Sprite 없이 기본 도형으로 표현한다. 코드의 도형 색과 크기는 기능 확인용 표현이며 최종 디자인 기준이 아니다.

### 기존 문서에서 정하지 않은 항목

`MENOS_DESIGN_SPEC.md`는 장르, 세계관의 핵심 판타지, 플레이어 역할을 정하지만 현실/애니메이션풍, 시대상, 외형, 정확한 색, 재질, 선화, 명암 방식은 고정하지 않는다. 이 항목들은 아래에서 모두 `PROPOSAL`로 제시한다.

## 2. 전체 Art Direction

### PROPOSAL — 시각적 방향

- **장르와 분위기:** 전술 방어와 슈퍼로봇 결전이 함께 읽히는 SF 전장. 위기감은 적과 기지의 크기·상태 대비로 만들고, 화면 장식은 핵심 전투를 가리지 않도록 제한한다.
- **기술 수준:** 현대 군사 장비의 익숙한 구조와 고성능 로봇 공학을 섞은 near-future 산업 SF를 제안한다. 특정 연도나 기술 연혁은 설정하지 않는다.
- **스타일:** 사실적인 비율과 애니메이션식 과장을 절충한다. 완전한 실사풍, 디젤펑크, 특정 국가/작품의 디자인 계보는 확정하지 않는다.
- **형태 언어:** Robot/Tower는 안정된 수직축, 평평한 장갑면, 읽기 쉬운 기계 관절을 사용한다. 적은 각 개체 역할에 맞춰 실루엣의 무게중심과 전진 방향을 달리한다.
- **외곽선:** 검은 두꺼운 만화 외곽선 대신 명암 경계와 제한적인 얇은 외곽선으로 작은 크기에서 형태를 분리한다.
- **명암:** 기본은 2~3단 셀 셰이딩. 넓은 면은 단순하게 유지하고, 작은 반사광은 금속 모서리와 에너지 부위에 한정한다.
- **색 사용:** 플레이어 측 Robot/Tower와 Enemy를 값(value)과 색 온도로 구분한다. 색만으로 적 종류를 판별하지 않도록 실루엣과 장갑 비율을 함께 사용한다. 정확한 팔레트는 시각 테스트 전 미정이다.
- **재질:** 도색 금속, 노출 금속, 복합 장갑, 고무/합성 관절, 에너지 발광을 재질 후보로 둔다. 녹, 기름때, 전투 손상량은 세계관 톤이 승인될 때까지 제한적으로만 제안한다.
- **디테일 밀도:** 기본 도형을 대체할 큰 형태를 먼저 정하고, 축소 화면에서 사라지는 패널선/볼트는 생략한다. 식별에 필요한 부위만 중간 크기 디테일로 남긴다.
- **작은 크기 가독성:** 역할별 외곽선, 무기 방향, 대형/소형 비율을 우선한다. 발광색이나 장식 문양만으로 역할을 설명하지 않는다.

### PROPOSAL — 색상 체계

- Robot: 차가운 계열의 주색과 밝은 중성 장갑을 조합하고, 센서/에너지만 제한된 강조색으로 둔다.
- Tower: 기지 소속임을 공유하는 중성 장갑색을 쓰되 Cannon에는 포신/장전부, Gatling에는 총열/회전부를 서로 다른 강조색 또는 형태로 구분한다.
- Enemy: 플레이어 측과 명도·색상군을 분리한다. Normal은 기본 적 색, Rusher는 빠른 실루엣 강조, Heavy는 넓은 장갑면, Giant는 큰 외곽선과 제한된 위험 표시로 구분한다.
- Godot PoC의 Robot 청록, Cannon 주황, Gatling 청록, 적별 임시 색은 `CONFIRMED` 팔레트가 아니다. 정확한 RGB/HEX는 여기서 정하지 않는다.

## 3. Robot Design Sheet — 최우선

### 기본 정보

- **이름:** ATLAS-01 / Robot (`CONFIRMED`, 현재 PoC 명칭)
- **역할:** 플레이어가 출격과 위치를 지시하는 핵심 전투 유닛. 이동 후 자동 교전하고 파괴될 수 있으며 재출격할 수 있다. (`CONFIRMED`)
- **게임 기능:** Basic Attack, 자동 Heavy Pierce, 다수 적 조건부 Area Attack, Giant에게 피격, 파괴/재출격. (`CONFIRMED` 기능 경로)
- **시각 중요도:** 최상. MENOS의 대표 캐릭터가 될 수 있다는 것은 기획 방향이며 상품 대표 디자인 확정은 아니다.
- **현재 PoC 크기:** Godot placeholder 원 반지름 22 px. (`CONFIRMED` 구현 수치, 목표 Sprite 크기 아님)
- **크기 제안:** 투명 여백 포함 64×64 px 기준 셀, 캐릭터 실제 바운딩 박스 약 48×56 px. `PROPOSAL`.
- **식별 핵심:** Enemy보다 정돈된 인간형/기계형 몸통, 명확한 머리·어깨·다리 구조, 장착 무기, 플레이어 소속 표시.

### 실루엣과 형태 — PROPOSAL

- 멀리서도 Giant/Heavy와 섞이지 않도록 머리와 양쪽 어깨, 두 다리가 읽히는 인간형 비율을 우선한다.
- 큰 흉부와 안정적인 다리 간격으로 슈퍼로봇의 존재감을 만든다. 과도한 어깨 뿔이나 날개는 피하고 무기·관절이 몸통 외곽과 겹치지 않게 한다.
- 이동 장비는 다리/발의 추진 구조 또는 짧은 기동 보조기 중 하나를 선택할 수 있도록 열어 둔다. 비행 가능 여부는 확정하지 않는다.
- Heavy의 사각 장갑 덩어리와 Giant의 거대한 넓은 몸통을 Robot에 그대로 반복하지 않는다.

### 색상·재질·무기 — PROPOSAL

- 도색 복합 장갑, 관절의 어두운 합성 소재, 센서와 에너지 부품의 발광을 재질 후보로 둔다.
- 발광색은 Robot과 Enemy를 빠르게 구분하는 데 사용하되 정확한 색과 위치는 승인 전 미정이다.
- Basic Attack은 반복 가능한 주무기 동작으로 읽혀야 한다. 현재 무기 종류가 코드에 정해져 있지 않으므로 총/빔/근접 무기 중 하나를 Canon화하지 않는다.
- Heavy Pierce는 Basic Attack과 확실히 다른 실루엣/에너지 집중 단계/발사선을 제안한다. 빔, 관통탄, 무기 변형 중 구체 방식은 `PROPOSAL`이다.
- Area Attack은 로봇 주변 범위를 한 번에 알아볼 수 있는 방사형 파동 또는 지면 타격을 후보로 둔다. 실제 VFX는 이번 문서 작업 범위 밖이다.

### Animation 요구사항 — 요구 상태 CONFIRMED, 연출 PROPOSAL

| 상태 | 목적 | 핵심 동작 제안 |
|---|---|---|
| Idle | 출격 후 대기/자동 전투 중 비공격 | 미세한 자세·센서 변화만 사용 |
| Move | 위치 명령 이동 | 목적지 방향으로 짧게 도약/추진하거나 보행. 즉시 위치 이동인 현재 PoC에 이동 애니메이션 시간을 추가할지는 별도 구현 결정 |
| Basic Attack | 일반 적 자동 공격 | 무기 조준과 짧은 발사/타격 동작 |
| Heavy Pierce | Heavy/Giant 대상 능력 | 에너지/무기 집중 후 강한 단발 동작으로 Basic과 구별 |
| Area Attack | 다수 적 능력 | 몸통 중심 동작과 주변 방향 확산을 제안 |
| Hit | 피격 인지 | 짧은 반동/점멸. Robot HP를 대체하는 장식이 되지 않도록 상태 표현과 분리 |
| Death | 파괴 인지 | 자세 붕괴 후 잔광/정지. 폭발 규모와 잔해 지속시간은 미정 |
| Deploy | 출격/재출격 인지 | 캡슐, 셔터, 순간 등장 중 형식은 미정. 현재 코드에 출격 연출은 없음 |

### 제작 제안 — PROPOSAL

- 기본 방향은 전투 대상 쪽을 향하는 3/4 측면. 현재 lane은 왼쪽에서 기지 쪽으로 진행하므로 기본 위협은 화면 오른쪽에서 다가오지만, 로봇 스프라이트의 기본 좌우 방향은 아트 파이프라인에서 결정한다.
- 투명 배경, 발밑 접점이 일정한 pivot, 고정된 바운딩 박스를 사용한다. Pivot은 발 사이 중심을 제안한다.
- 좌우 반전은 비대칭 무기/어깨 장식이 시각적으로 바뀌므로, 단순 미러링 가능 여부를 최종 모델 승인 후 결정한다.
- 분리 가능한 본체/무기/발광 이펙트 레이어를 검토한다. Sprite Sheet는 Idle/Move/Attack/Hit/Death 상태를 한 장 또는 상태별 Atlas로 묶는 안 모두 가능하다.
- 제안 프레임: Idle 4, Move 6, Basic 4, Heavy Pierce 5, Area 5, Hit 2, Death 6, Deploy 4. 프레임 수·재생 속도는 모두 미확정 제안이다.

## 4. Enemy Design Sheets

네 Enemy는 공통 조명·재질 규칙을 공유하되, 흉부 크기만 바꾸는 변형으로 끝내지 않는다. 정확한 종족/기원/생물 여부는 설정되지 않았다.

### Normal

- **역할 / 기능:** 기본 Enemy. HP·Armor가 낮은 기준 적으로 양쪽 접근로를 이동하고 Base에 피해를 준다. (`CONFIRMED` 코드 역할)
- **중요도:** 기준 실루엣. 다른 적의 비율 차이를 비교하는 기준.
- **현재 크기:** Godot placeholder 반지름 10 px. **크기 제안:** 24×24 px 셀, 실제 실루엣 18×20 px.
- **실루엣·형태 제안:** 짧고 단순한 몸통, 2~4개의 읽기 쉬운 사지/추진부. 장갑 돌출을 최소화한다. 원형/작은 실루엣을 쓰더라도 Rusher와 정지된 형태가 겹치지 않게 한다.
- **색·재질 제안:** Enemy 공통 색군 안에서 기준색 사용. 경량 장갑 또는 단순 기계/외골격 재질. 특정 생물형/기계형 선택은 미정.
- **장비:** Base를 향한 단순 돌격 장비/무장 가능. 원거리 공격은 코드 기능이 아니므로 디자인만으로 사격 기능을 암시하지 않는다.
- **Animation 제안:** Idle 2, Move 4, Hit 2, Death 4. 이동은 일정한 기본 속도감.
- **Sprite 제안:** 진행 방향이 명확한 3/4 측면, 발/바퀴 접점 중심 pivot, 좌우 lane용 반전은 대칭 디자인일 때만 허용. 별도 공격 Animation은 현재 코드 역할상 필수 아님.

### Rusher

- **역할 / 기능:** Normal보다 빠르게 진입하는 Enemy. 코드에는 일정 진행 후 sprint 속도 증가가 있다. (`CONFIRMED`)
- **중요도:** 속도 위협을 실루엣만으로 먼저 읽히게 한다.
- **현재 크기:** Godot placeholder 반지름 8 px. **크기 제안:** 24×24 px 셀, 낮고 앞쪽으로 긴 실루엣 20×16 px.
- **실루엣·형태 제안:** 몸통을 진행 방향으로 기울이고, 뒤쪽 추진부/긴 다리/낮은 중심 중 하나를 사용한다. Normal보다 작거나 길게 만들어 단순 색상 교체를 피한다.
- **색·재질 제안:** Normal과 같은 Enemy 색군을 공유하고, 속도 식별을 위한 제한된 강조부를 추가한다. 정확한 색은 미정.
- **장비:** 가벼운 장갑과 추진 구조를 제안. 무기 보유 여부는 확정하지 않는다.
- **Animation 제안:** Idle 2, Move 6, Sprint 4, Hit 2, Death 4. Sprint는 발/추진 흔적의 주기와 몸통 기울기를 높여 단계 변화를 전달한다.
- **Sprite 제안:** 기본 이동 방향과 일치하는 측면/3/4. pivot은 지면 접점 중앙. 좌우 반전은 장비 대칭 여부 확인 후 결정.

### Heavy

- **역할 / 기능:** 높은 HP와 Armor를 가진 느린 중장갑 Enemy. Cannon과 Robot Heavy Pierce의 대상군이다. (`CONFIRMED`)
- **중요도:** Normal/Rusher보다 무겁고 단단한 방어 대상.
- **현재 크기:** Godot placeholder 반지름 15 px. **크기 제안:** 40×40 px 셀, 실루엣 34×36 px.
- **실루엣·형태 제안:** 넓은 상체/전면 장갑, 낮은 무게중심, 짧고 굵은 다리 또는 견고한 주행부. Normal보다 폭과 높이가 확연히 커야 한다.
- **색·재질 제안:** Enemy 공통 색군을 유지하되 넓은 무광 장갑면과 마모 가장자리로 내구성을 표시한다. 실제 장갑 재질은 미정.
- **무장:** Base 방향 위협을 암시하는 무장/충각 장비는 후보지만, 코드상 별도 공격 동작은 없으므로 특정 무기 능력처럼 표현하지 않는다.
- **Animation 제안:** Idle 2, Move 4(큰 관성), Hit 2(작은 반동), Death 5. 피격 반응은 Rusher보다 무겁게.
- **Sprite 제안:** 3/4 측면, 발/궤도 중심 pivot. 대칭 장갑이면 좌우 반전 가능. 잔해/파괴 프레임은 Giant와 겹치지 않도록 크기 대비 유지.

### Giant

- **역할 / 기능:** Wave 4의 거대 Enemy이자 현재 가장 큰 위협. Base에 큰 피해를 줄 수 있고 Robot과 직접 교전한다. (`CONFIRMED`)
- **중요도:** 보스급 전투 개체. 등장 순간 Robot 및 방어선과 쉽게 구별되어야 한다.
- **현재 크기:** Godot placeholder 반지름 28 px. **크기 제안:** 72×72 또는 80×80 px 셀, 실루엣 약 64×72 px.
- **실루엣·형태 제안:** Heavy의 단순 확대가 아니라 다른 어깨/머리/팔 구조와 고유한 외곽을 사용한다. 화면에서 Robot과 맞붙었을 때 양쪽 형태가 겹치지 않도록 머리·팔·몸통의 음영 여백을 둔다.
- **장갑·무장 제안:** 넓은 장갑판, 큰 팔/상체, Robot을 위협하는 공격부위를 제안한다. Giant 공격 방식은 코드에서 직접 타격 수치만 확인되므로, 발톱·포·근접 타격 중 하나를 확정하지 않는다.
- **색·재질 제안:** 일반 적과 같은 진영 색군을 유지하면서 큰 명도 블록과 소수의 위험 강조부를 사용한다. 발광 핵/약점은 현재 기능이 아니므로 제안으로만 둔다.
- **Animation 제안:** Idle 3, Move 6(큰 보폭), Robot Attack 5, Base Breach 4(공격 동작이 정해질 경우), Hit 3, Death 8. Robot 공격과 Base 도달을 같은 애니메이션으로 처리할지는 미정.
- **Sprite 제안:** 로봇과 맞붙는 3/4 측면. 발 접점 pivot. 좌우 반전 시 공격부 방향이 바뀔 수 있어 비대칭 무장 여부를 확인한다. 크기 차이는 축소 화면에서도 Giant가 두 배 이상 존재감을 갖도록 검토한다.

## 5. Tower Design Sheets

### Cannon

- **역할 / 기능:** Heavy/Giant를 선호하는 느린 주기의 높은 단발 피해 Tower. (`CONFIRMED`)
- **중요도:** 기지 방어선의 중화기.
- **현재 크기:** Godot placeholder 반지름 15 px. **크기 제안:** 48×48 px 셀, 기단 포함 실루엣 38×42 px.
- **실루엣·형태 제안:** 안정된 기단, 한 개의 굵고 긴 포신, 포신 뒤쪽 장전/반동 구조. Gatling의 다중 총열과 먼 거리에서도 구분한다.
- **색·재질 제안:** 플레이어 방어시설 공통 중성 도색 금속. 포신/열 배출부에 제한적인 강조색. 정확한 팔레트 미정.
- **무기 표현:** 회전 또는 제한 각도 조준 구조와 포탄 발사를 후보로 둔다. 현재 코드상 projectile은 없으므로 포탄 디자인/탄두 유형은 미정 제안.
- **Animation 제안:** Idle 1~2, Aim 2~3, Fire 3(포신 반동/짧은 섬광), Reload 3, Hit/Destroyed는 기능 필요 여부 미정.
- **Sprite 제안:** 위에서 본 3/4 탑다운. 기단 중심 pivot, 포신 방향으로 aim anchor를 분리하는 방안. 좌우 반전보다 회전 가능한 포탑 구조를 권장하는 것은 제안이다.

### Gatling

- **역할 / 기능:** Normal/Rusher를 선호하는 빠른 연사 Tower. (`CONFIRMED`)
- **중요도:** 경량 적을 지속적으로 제압하는 방어시설.
- **현재 크기:** Godot placeholder 반지름 15 px. **크기 제안:** 48×48 px 셀, Cannon과 같은 기단 크기에서 총열 방향이 구분되는 실루엣.
- **실루엣·형태 제안:** 여러 개의 짧은 총열 묶음, 노출된 회전 축/급탄부, Cannon보다 짧고 넓은 상부 구조. 한 개의 긴 포신 형태는 피한다.
- **색·재질 제안:** Cannon과 같은 기지 소속 팔레트. 총열 회전부/열 배출부의 색 또는 명도 대비로 기능을 구분한다.
- **무기 표현:** 총열 회전과 빠른 연사 표시를 후보로 둔다. 현재 Projectile/VFX는 없으며 탄흔/탄피의 최종 양은 미정이다.
- **Animation 제안:** Idle 1~2, Aim 2~3, Fire 2~4 반복(총열 회전/연속 발사), Heat/Reload는 게임 기능과 시각 필요가 확인되기 전 미정.
- **Sprite 제안:** Cannon과 동일한 카메라·기단·축척으로 한 세트처럼 제작. 회전부를 별도 레이어로 둘 수 있다. pivot은 기단 중심.

## 6. 공통 Sprite 제작 규칙 — PROPOSAL

- 투명 배경 PNG 또는 프로젝트가 선택할 무손실 RGBA 포맷. 배경색이나 임시 맵을 Sprite에 포함하지 않는다.
- 같은 장면의 광원 방향과 명암 단계를 공유한다. 광원 방향은 첫 Sprite test에서 정하고 승인받는다.
- 각 원본은 1× 기준 크기로 제작하고, 축소 시 식별성을 확인한다. Pixel-art인지 고해상도 painted sprite인지는 아직 정하지 않는다.
- Character는 발 접점, Tower는 기단 중심을 pivot 기준으로 삼는 안을 제안한다. Giant의 발 위치와 대형 사망 상태에서도 접점이 튀지 않는지 확인한다.
- 모든 Animation은 동일 바운딩 박스와 기준점 유지. 무기/발광부를 분리할 경우 별도 layer/attachment 기준을 문서화한다.
- Sprite Sheet는 캐릭터별/타워별 Atlas를 권장하되, 최종 프레임 크기와 Godot import 방식은 승인 후 결정한다.
- 제안 크기와 프레임 수는 아트 테스트용 출발점이며 게임 좌표, collision shape, 카메라 zoom과 함께 확정해야 한다.
- 화면상 팀 식별은 silhouette와 명암 대비를 우선하고, 색각 차이가 있어도 크기·무기·장갑 형태로 역할을 읽을 수 있어야 한다.

## 8. 일관성 및 DESIGN ISSUE

### 일관성 점검

- **Robot과 Enemy:** 같은 기술 세계의 기계/장갑 규칙을 공유하되, Robot은 플레이어 측의 정돈된 형태와 인간형 실루엣, Enemy는 역할별 변형으로 구분하는 안이다. 모두 기계인지 생물인지 여부는 미정.
- **Enemy 4종:** Normal은 기준, Rusher는 전진·경량, Heavy는 낮고 넓은 장갑, Giant는 압도적 크기와 고유한 상체 실루엣으로 구분한다.
- **Cannon/Gatling:** 동일한 기단·광원·재질 언어를 쓰고, 포신 길이와 총열 묶음으로 역할을 분리한다.
- **Giant:** Godot placeholder 크기는 Robot보다 크지만, 실제 Sprite에서도 어느 정도 차이가 적절한지 축소 화면 테스트가 필요하다.
- **색상:** 현 코드 색은 placeholder이므로 production palette 충돌 여부를 아직 판단할 수 없다.
- **축소 가독성:** 제안된 픽셀 크기는 코드에서 사용 중인 Godot placeholder 크기를 출발점으로 삼았다. 실제 카메라 zoom별 판독성은 확인되지 않았다.

### DESIGN ISSUE — 제작 전 확인 필요

1. **카메라/축척:** 현재 PoC 도형 반지름은 있으나 최종 카메라 zoom과 화면상 목표 크기는 확정되지 않았다. 이를 모르면 픽셀/프레임 제안의 적정성을 판단하기 어렵다.
2. **스타일 매체:** Pixel art, hand-painted, vector-like cel shading 중 선택이 없다. 이 문서는 2~3단 명암만 제안하고 매체는 결정하지 않는다.
3. **Enemy 정체성:** 코드상 유형은 전투 역할로만 정의된다. 기계, 생물, 외계 종족 중 어느 것으로 그릴지는 미정이다.
4. **Robot 무기:** Basic Attack 및 Heavy Pierce 기능은 있으나 무기 외형/공격 방식이 정해져 있지 않다.
5. **Godot/Browser data 차이:** Giant 수치와 기존 PoC 표현이 환경별로 다를 수 있다. 시트 크기/외형에는 직접 영향이 없지만 전투 Animation 타이밍을 수치에 맞춰 제작하기 전 Godot 주력 기준을 확인해야 한다.
6. **피격 방향/좌우 반전:** 현재 전투는 자동 타겟이지만 캐릭터 facing 규칙과 lane별 방향 전환 규칙은 시트 제작 전에 정해야 한다.

현재 확인 자료만으로 7개 개체 간 확정된 시각 충돌은 없다. 위 항목은 충돌 판정이 아니라 제작자가 임의로 결정하면 안 되는 공백이다.

## 9. PROPOSAL 목록

Master가 승인하거나 수정할 수 있는 제안 목록:

1. 스타일: near-future 산업 SF와 애니메이션식 과장을 섞은 방향.
2. 형태 언어: 플레이어 측은 정돈되고 안정된 기계 형태, Enemy는 역할별 무게중심과 돌출부로 분리.
3. 외곽선/명암: 두꺼운 검은 선보다 얇은 edge separation과 2~3단 셀 셰이딩.
4. 팔레트: Robot/Tower는 공통 플레이어 측 색군, Enemy는 별도 적 색군. 정확한 색 값은 승인 후 색상 테스트.
5. 제안 기준 셀: Robot 64×64, 일반 Enemy 24×24, Heavy 40×40, Giant 72~80, Tower 48×48.
6. 위에서 제안한 Idle/Move/Attack/Hit/Death/Deploy 프레임 수.
7. Robot의 인간형 체형, 기본 방향, 이동 장비, 무기 종류, Heavy Pierce 형태.
8. Enemy가 기계/생물 중 무엇인지, Giant 공격 방식과 손상/파괴 표현.
9. Sprite 매체, 카메라 방향, 광원 방향, 좌우 반전 허용 규칙, Godot Atlas/import 설정.

## 10. UNVERIFIED / 참고자료

- 실제 Sprite 제작자 테스트를 통한 작은 크기 가독성, 개체 식별성, Giant와 Robot의 화면 균형.
- 최종 카메라 zoom/해상도별 픽셀 크기와 프레임 재생 속도.
- 색상 대비와 접근성.
- 기존 코드의 임시 도형 색/크기가 최종 팔레트와 연결된다는 근거는 없다.
- 이번 문서 작성에는 외부 이미지나 외부 디자인 자료를 사용하지 않았다. 기존 기획 문서와 프로젝트 코드만 참고했다.
